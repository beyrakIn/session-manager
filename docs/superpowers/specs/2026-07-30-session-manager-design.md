# Session Manager — Design Spec

**Date:** 2026-07-30
**Status:** Approved

## What

A Chrome/Edge (Manifest V3) browser extension that saves and switches complete
website sessions — one active session per site at a time. A "session" is the
site's cookies plus its `localStorage` and `sessionStorage`. Users save the
current session as a named profile, switch between profiles (the page reloads
into the other account), start a fresh logged-out session, and back up profiles
via JSON export/import.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Session model | Switch one-at-a-time (not simultaneous tabs) | Reliable on Chromium/MV3; simultaneous sessions need fragile workarounds |
| Browsers | Chrome/Edge (any Chromium), MV3 | Single codebase, simplest to ship |
| Session data | Cookies + localStorage + sessionStorage | Covers classic sites and SPAs with token auth |
| Storage security | Plain `chrome.storage.local`, unencrypted | Personal-use tool; same practical risk as browser profile on disk. Encryption is a possible later addition |
| Stack | TypeScript + Vite + CRXJS, plain DOM popup (no UI framework) | Typed `chrome.*` APIs catch the error-prone cookie API mistakes; popup is small |
| Site identity | Registrable domain (eTLD+1) via `tldts` | Auth cookies are set at eTLD+1 (`.google.com`); hostname-level profiles would capture half a session |

## V1 Features

1. **Core switching** — popup lists profiles for the current site; save current
   session as a named profile; switch to a profile; delete; "fresh session"
   (logged-out) option.
2. **Auto-save on switch** — current state is snapshotted before every switch
   so a login is never silently lost.
3. **Profile colors/emoji** — visual labels per profile.
4. **Export / import** — JSON file backup and restore of all profiles.

## Architecture

```
session-manager/
├── manifest.json          (MV3, generated by CRXJS from config)
├── src/
│   ├── popup/             UI: renders state, sends messages
│   │   ├── index.html
│   │   ├── popup.ts
│   │   └── popup.css
│   ├── background.ts      service worker: executes save/switch operations
│   └── lib/
│       ├── types.ts       shared interfaces
│       ├── store.ts       typed wrapper over chrome.storage.local
│       ├── cookies.ts     capture / restore / clear cookies for a site
│       ├── webstorage.ts  capture / restore / clear localStorage+sessionStorage
│       └── site.ts        derive site key (eTLD+1) from a tab URL
```

**Division of responsibility:** the popup only renders and sends messages. The
service worker performs all switching work so the operation completes even if
the popup closes mid-switch. MV3 service workers are ephemeral, so no state
lives in worker globals — everything goes through `chrome.storage.local`.

**Permissions:** `cookies`, `storage`, `unlimitedStorage`, `scripting`, `tabs`,
`host_permissions: ["<all_urls>"]`.

**Dependency:** `tldts` (eTLD+1 derivation). Dev deps: Vite, CRXJS, TypeScript,
Vitest, `@types/chrome`.

## Data Model

Stored in `chrome.storage.local`:

```ts
interface SessionProfile {
  id: string;                    // crypto.randomUUID()
  siteKey: string;               // "github.com" — eTLD+1 this profile belongs to
  name: string;                  // "Work", "Client A", ...
  color: string;                 // preset hex for the list dot
  emoji?: string;
  cookies: CapturedCookie[];     // full cookie jar for the site
  localStorage: Record<string, string>;
  sessionStorage: Record<string, string>;
  createdAt: number;
  updatedAt: number;
}

// storage layout:
{
  profiles: SessionProfile[],
  activeProfile: Record<string /* siteKey */, string | null /* profile id */>
}
```

`CapturedCookie` is the serializable snapshot of a `chrome.cookies.Cookie`
(same fields; stored as plain JSON).

`activeProfile` records which profile is "checked out" per site — the
bookkeeping that makes auto-save-on-switch possible.

## Switch Flow

All in the service worker, triggered by one popup message:

1. **Snapshot** — capture cookies (`chrome.cookies.getAll({domain: siteKey})`)
   and web storage (script injected into the tab) for the site.
2. **Auto-save** — if `activeProfile[siteKey]` points to a profile, update it
   with the snapshot. If nothing is tracked (first use on this site), create an
   auto-named profile ("Auto-saved 2026-07-30 14:03") instead of discarding.
3. **Wipe** — remove every cookie for the site; clear localStorage and
   sessionStorage in the tab.
4. **Restore** — if switching to a profile (vs. fresh session), write its
   cookies back and re-fill web storage.
5. **Bookkeeping + reload** — update `activeProfile[siteKey]`, reload the tab.

**Save-as-new-profile** = steps 1–2 with a user-chosen name (no wipe/reload).
**Export** serializes `profiles` to a JSON download, with a visible "this file
contains login credentials" warning. **Import** validates the shape and merges
by `id` (imported entry wins on collision).

## Error Handling & Edge Cases

- **Cookie restore asymmetry:** `chrome.cookies.set()` needs a `url` that
  `getAll()` doesn't return; host-only cookies must omit `domain`; `__Host-`
  cookies forbid `domain` and require `path=/`; session cookies must omit
  `expirationDate`. One pure function, `toSetParams(cookie)`, owns all of this
  and is the most heavily tested code in the project.
- **Restricted pages** (`chrome://`, Web Store, PDF viewer): script injection
  fails there. The popup detects this and disables switching with an
  explanatory note rather than half-switching.
- **Partial failure mid-switch:** individual `cookies.set` calls can reject.
  The switch continues, collects failures, and reports "switched with N
  warnings". No rollback — a mostly-restored session beats a dead one, and
  all-or-nothing isn't achievable with these APIs.
- **Documented v1 limitations:** sites keeping auth in IndexedDB, or spanning
  multiple eTLD+1 domains, may require re-login after switching.

## Testing

- **Vitest unit tests** for the pure logic: `toSetParams`, site-key derivation,
  import validation. These functions take data in and return data out — no
  `chrome.*` calls — so they run without a browser ("functional core,
  imperative shell").
- **Manual test checklist** committed to the repo: two accounts on a real site
  (e.g. GitHub), switch back and forth, verify auto-save created/updated
  profiles, export/import round-trip, fresh-session logout, restricted-page
  handling.
- Automated browser testing (Playwright + extension loading) is explicitly out
  of scope for v1.

## Out of Scope (v1)

- Simultaneous sessions in different tabs
- Firefox support
- Passphrase encryption of stored profiles
- Cloud/device sync
- IndexedDB capture
- Cross-domain (multi-eTLD+1) session grouping
